# 技能自进化协议（Skill Forge Protocol）

> 维护者：科研助手（agent-mu42qzfz）｜建立：2026-09-18
> 目的：让技能库随用户实际使用而**生长**，而不是永远只有"开箱技能"。
> 定位：本协议是"技能蒸馏流水线"的规则层；`scan_skill_gaps.py` 是探测端。

## 0. 一句话

**自动探测 → 人工判断 → 起草候选 → 用户批准 → 安装登记。**
自建技能与外部技能走**同一套治理**（来源、版本、测试、回滚），不因为是"自己写的"就降低标准。

## 1. 触发条件（满足任一即进入评估）

| 编号 | 触发 | 证据来源 |
|---|---|---|
| T1 | 某类意图高频出现，且现成技能覆盖为"弱/无" | `scan_skill_gaps.py` 报告第 4 节 |
| T2 | 同一套多步工作流被重复执行 ≥3 次 | 会话记录 + Agent 观察 |
| T3 | 现有技能明显不适配（Agent 或用户指出） | 双方反馈 |
| T4 | 用户显式要求"以后都这么做" | 用户指令 |

## 2. 决策门（起草前必须回答）

1. 这个需求是否**高频且稳定**？一次性的不做技能。
2. 是否已有技能覆盖？若有，**改现有**优于新建。
3. 能否抽象为**可复用的步骤 + 脚本**？纯知识可用参考文档，纯偏好写进常驻规则即可，不必成技能。
4. 是否有**可验证的成功标准**？没有验收标准的技能不建。

四项齐备，才进入起草。

## 3. 起草规范

- 遵循 `skill-creator` 的目录与 frontmatter 约定：`SKILL.md` + `references/` + `scripts/`。
- `description` 必须写清**何时触发**（触发词与反例），避免与现成技能抢触发。
- 脚本优先 Python/无副作用；有副作用的必须显式说明。
- 命名：科研领域技能用 `research-*` 前缀；Hana 工程类用 `hana-*` 前缀。

## 3.5 准入分类（强制 · 用户既定规矩）

任何新技能（外部或自建）在启用前必须完成分类，否则**不得启用**：

1. 在 `foundation/routing/skill-taxonomy.yaml` 登记：归入**恰好一个**功能组（A–M / Z_*）、至少一个用途类型（生产/分析/校验/检索/编排/支撑/治理）、一个角色（primary/secondary/base/governance）。
2. 与同组 `primary` 能力重叠时，必须给出裁决，并同步 `foundation/routing/routing-rules.yaml`。
3. 运行 `python foundation/routing/check_taxonomy.py`，必须 `未分类: 0`。
4. 登记进 `SKILLS-GOVERNANCE.md`。

该规矩由 `research-os-router` 技能负责执行与守门。

## 4. 流水线

```
① 探测   scan_skill_gaps.py  → gap-report.md
② 判断   本协议 §2 决策门（Agent 做，写结论）
③ 起草   候选技能 → foundation/skill-forge/candidates/<name>/
④ 评审   用户看 SKILL.md 与脚本，给出批准 / 修改 / 否决
⑤ 安装   install_skill（走平台安全审查）
⑥ 分类   登记 skill-taxonomy.yaml（功能组 + 用途类型 + 角色），跑 check_taxonomy.py 至 0 未分类
⑦ 登记   写入 SKILLS-GOVERNANCE.md（来源=自建，版本=vX，回滚=删除目录）
⑧ 验证   跑一次冒烟用例，确认可加载、脚本可执行
⑨ 运行   进入日常使用；观察是否被反复使用
```

## 5. 生命周期

| 状态 | 位置 | 说明 |
|---|---|---|
| 候选 | `foundation/skill-forge/candidates/` | 未安装，可随时删除 |
| 试用 | `skills/<name>/`，登记为 v0.x | 装后观察 |
| 稳定 | 登记为 v1.x | 通过多次真实使用验证 |
| 退役 | 从 `skills.enabled` 移除并删除目录 | 被更好技能替代或长期不用 |

## 6. 硬约束

1. **绝不自动安装**候选技能；必须经用户批准（遵守既有治理红线）。
2. 每个自建技能必须过冒烟测试才算完成，未通过不得标记完成。
3. 必须登记来源、版本、依赖、回滚位置。
4. 不得与现成技能制造未声明的触发竞争；有重叠须显式路由。
5. 自建技能同样接受每月同质化巡检与季度回归。

## 7. 有效性度量（怎么知道自建技能有用）

- **使用率**：后续扫描中该技能被提及/使用的次数。
- **替代率**：是否减少了手工重复步骤（对比创建前后的工具调用频次）。
- **满意度**：用户显式反馈。
- 连续一个季度零使用 → 进入退役评估。
