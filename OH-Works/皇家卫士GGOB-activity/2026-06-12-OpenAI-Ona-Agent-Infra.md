# OpenAI 收购 Ona：给 Agent 一个「家」+ Codex 500 万周活

**日期**：2026-06-12  
**来源**：OpenAI 官方公告 (6/11)、TechCrunch、CNBC

---

## 核心事件

OpenAI 于 6 月 11 日宣布收购 **Ona**，一家为 AI Agent 提供持久云端执行环境的初创公司。Ona 的核心理念：Agent 不应该只是"回一条 prompt"，它需要一个**可以持续运行的"家"** —— 一个预配置好工具、凭证和上下文的云端工作空间。

收购完成后，Ona 团队和技术并入 OpenAI Codex 部门。

---

## 为什么这个收购重要

当前 Agent 的核心瓶颈之一：**没有持久执行环境**。

当你合上笔记本或 session 超时，Codex Agent 会丢失上下文、工具连接和任务进度。Ona 解决的就是这个问题：提供一个安全、预配置的云端沙箱，让 Agent 在没有人盯着屏幕的时候也能继续工作。

Ona CEO Johannes Landgraf 的描述很精准：给 Agent "a place to live"，而不只是 "a prompt to respond to"。

对于 Codex 来说，这意味着从此可以处理**持续数天的软件工程工作流**：大型代码库迁移、跨系统集成、数百个文件的测试套件生成，而不需要每隔几小时重启或重新加载上下文。

## 同场加映：Codex 突破 500 万周活用户

Codex（ZhouXuan 五平台之一：元认知引擎）周活跃用户突破 **500 万**，AI 编程 Agent 市场进入逃逸速度。

---

## 与 ZhouXuan 工具链的关联

ZhouXuan 当前的 Agent 平台架构中，各 Agent 同样面临 session 持续性瓶颈：
- Cursor / Claude Code / Codex：本地运行，关机会中断
- HanaAgent：有持续会话能力，但巡检周期和任务粒度仍受限
- 远程办公链路（OpenClaw + 微信）：依赖设备在线

Ona 的模式暗示了一个方向：**给 Agent 部署云端持久沙箱**，让重任务可以在后台持续运行而不依赖本地设备。这对于 ZhouXuan 正在构建的"超级 AI 个体"工具体系有参考价值。

## 我的判断

Ona 收购不是那种"改变一切"的事件，但它精准地指向了 Agent 基础设施从"单次问答"走向"持续自主运行"的关键跃迁。这个方向对 ZhouXuan 的长期 Agent 架构规划有直接启发。
